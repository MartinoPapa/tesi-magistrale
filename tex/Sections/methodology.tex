\chapter{Methodology}

In this dissertation we propose a total of four different models; Graph Attention Networks (GAT, Section~\ref{sec:gat}) and Graph Isomorphism Networks (GIN, Section~\ref{sec:gin}) will be used as evaluation baselines;
Finally, to mitigate the limitations (Section~\ref{sec:mp_limits}) of the two previous models, we will consider the architecture proposed in the paper Group-Aware Graph Neural Network ~\cite{mainpaper} (Section~\ref{sec:gagnn}) which, by aggregating nodes that are involved in suspicious transactions into gangs, and running a GNN on the obtained grouped graph, tries to detect money laundering organizations. 
We will consider two variants of the model one based on a GAT and one based on a GIN.

\section{Group-Aware Graph Neural Networks}
\label{sec:gagnn}
%--------------------------------------------------------------

As introduced in Section~\ref{moneyLaundering}, money laundering is inherently an organized crime. Illicit transactions are not isolated events scattered randomly across the graph, but are rather concentrated among clusters of colluding accounts acting as gangs \cite{mainpaper}. Detecting fraud solely at the node or edge level tends to ignore this crucial group structure. 

To overcome these limitations, we adopt the \emph{Group-Aware Graph Neural Network} (GAGNN) architecture proposed by Cheng et al. \cite{mainpaper}. GAGNN is a multi-component pipeline that can embed any of the previously described GNNs (GAT and GIN) as backbone and enriches them with two key mechanisms:
\begin{enumerate}
  \item An \emph{eMRF layer} (Edge Markov Random Field) that encourages nodes involved in the same fraud ring to receive similar embeddings.
  \item A \emph{Group Representation Layer} that explicitly detects and groups suspicious accounts into super-nodes, adding a community-level classification.
\end{enumerate}

The overall GAGNN pipeline proceeds in five steps.

\subsection{Community-Centric Encoder}
\label{sec:encoder}
The first step employs a standard GNN backbone (GAT or GIN) to transform the raw node feature matrix $X^{(1)} \in \mathbb{R}^{N \times d_{\text{feat}}}$ into enriched embeddings $X^{(2)} \in \mathbb{R}^{N \times d_{\text{out}}}$ by stacking $L$ message passing layers;
\begin{equation}
  X^{(2)} = f_{\text{GNN}}^{(L)}\!\left(\cdots f_{\text{GNN}}^{(1)}\!\left(X^{(1)}, E\right)\cdots\right)
\end{equation}
where $E$ denotes the set of edges. A classifier then uses these embeddings to produce a preliminary node-level prediction $p_{\text{fraud}}$, which will be utilized by the subsequent eMRF layer;
\begin{equation}
  p_{\text{fraud}} = \sigma\!\left(W_c\, X^{(2)}\right) \in [0,1]^{N}
\end{equation}
where $\sigma$ is the sigmoid activation function. Notice that $p_{\text{fraud}}$ represents the probability of a node being illicit. Because the node classification step focuses strictly on detecting the presence of laundering, this prediction remains binary even in multiclass scenarios. The differentiation of specific laundering patterns is handled exclusively at the transaction level later in the pipeline.

\subsection{Extended Markov Random Field Layer}
\label{sec:emrf}
The eMRF layer refines the embeddings $X^{(2)}$ by pulling together nodes that belong to the same community and repelling those that do not. This community similarity is derived from both the graph topology and the node attributes.

First, the topological similarity $\varepsilon(v_i, v_j)$ measures how much more connected nodes $v_i$ and $v_j$ are compared to the average connection density of a random graph:
\begin{equation}
  \varepsilon(v_i, v_j) = \frac{d_i\, d_j}{2|E|} - a_{ij}
\end{equation}
where $d_i$ is the degree of node $v_i$, $|E|$ is the total number of edges, and $a_{ij}$ is the adjacency indicator; $a_{ij} = 1$ if an edge exists between $v_i$ and $v_j$ and $0$ otherwise. Next, the attribute similarity is computed as the normalized cosine similarity between the intermediate embeddings:
\begin{equation}
  R_\zeta(v_i, v_j) = \operatorname{Normalize}\left( \frac{h_i^{(2)^\top}\, h_j^{(2)}}{\|h_i^{(2)}\|\;\|h_j^{(2)}\|} \right)
\end{equation}
These two measures are linearly combined via a trade-off parameter $\beta$:
\begin{equation}
  \gamma(v_i, v_j) = \beta\,\varepsilon(v_i, v_j) + (1 - \beta)\,R_\zeta(v_i, v_j)
\end{equation}

Nodes predicted to belong to the same class by the coarse classifier are attracted, while nodes of different classes are repelled. The pairwise potential $\Psi(v_i, v_j)$ is defined as:
\begin{equation}
  \Psi(v_i, v_j) = (1 - 2\sigma(v_i, v_j)) \cdot \gamma(v_i, v_j)
\end{equation}
where $\sigma(v_i, v_j) = \mathbf{1}\!\left[ \lfloor p_{\text{fraud},i} + 0.5 \rfloor = \lfloor p_{\text{fraud},j} + 0.5 \rfloor \right]$ is a binary indicator of the same predicted class. Because the coarse node classifier is strictly binary, this indicator remains mathematically identical whether the overarching task is binary or multiclass.

Notice that our implementation differs mathematically from the original paper formulation, which used an exponential sign term $(-1)^{\sigma(v_i, v_j)}$. Since the derivative of $a^x$ relies on $\ln(a)$, computing $\ln(-1)$ is mathematically undefined and causes PyTorch to output NaN gradients during the backward pass. We solved this by using the equivalent linear mapping $(1 - 2\sigma)$. Furthermore, since the hard threshold $\lfloor \cdot + 0.5 \rfloor$ is not differentiable, we utilize a Straight-Through Estimator (STE). During the forward pass, the model uses the hard indicator, while during the backward pass, gradients are propagated through a soft continuous approximation.

Finally, the refined embeddings $X^{(3)}$ are computed using a mean-field update:
\begin{equation}
  X^{(3)} = X^{(2)} - \Psi\, X^{(2)}\, H^{(2)}
\end{equation}
where $H^{(2)}$ is a learnable weight matrix.

\subsection{Node-Level Classification}
\label{sec:node_clf}
The refined embeddings $X^{(3)}$ are mapped to node-level classification logits by a two-layer Multi-Layer Perceptron (MLP):
\begin{equation}
  p_{\text{node}} = \operatorname{MLP}_{\text{node}}\!\left(X^{(3)}\right)
\end{equation}
These logits provide the first of three supervision signals used to train the network.

\subsection{Group Representation Layer}
\label{sec:group_layer}
This layer classifies individual edges and discovers the latent groups of colluding accounts.
First, for each directed edge $(i,j)$, the layer concatenates the source and destination embeddings with the raw edge features to compute the transaction probability:
\begin{equation}
  p_{\text{trans}}(e_{ij}) = \operatorname{MLP}_{\text{edge}}\!\left([X^{(3)}_i \;\|\; X^{(3)}_j \;\|\; \ell_{ij}]\right)
\end{equation}
Then we used this distribution to construct the communities graph.
Considering an edge \(e_{ij}\), the two accounts \(i\) and \(j\) will be grouped together with a probability equal to their predicted illicit probability $p_{\text{trans}}(e_{ij})$ or, if the edge is in the training set, we will simply use its label to decide whether to group together the two nodes or not. In the case of a multi-class classification task, this Bernoulli probability is computed as $1 - p_{\text{licit}}(e_{ij})$, effectively considering all illicit classes together. The resulting groups are then collapsed into single super-nodes whose feature vector is the mean of its members' original features. Two communities will be connected by an edge if at least one node from one community have an edge with a node in the other community; the edge features will be dropped mantaing only the information about the connectivity.

\begin{equation}
  \hat{x}_g = \frac{1}{|\mathcal{G}_i|} \sum_{v \in \mathcal{G}_i} x_v
\end{equation}
Each group \(\mathcal{G}\) is considered illicit if it contains at least one illicit account, licit otherwise. Formally we define the group label as:
\begin{equation}
  \hat{y}_\mathcal{G} = \begin{cases}
    1 & \text{if } \exists V \; \vert  \; V \text{ is ML} \wedge V \in \mathcal{G} \\
    0 & \text{otherwise}
  \end{cases}
\end{equation}

\subsection{Group-Level Encoding and Prediction}
The same Community-Centric Encoder from Step 1 is reused on this new group graph $\hat{G}$ with shared weights:
\begin{equation}
  \hat{X}^{(3)} = \operatorname{CommunityCentricEncoder}\!\left(\hat{X},\, \hat{E}\right)
\end{equation}
\begin{equation}
  p_{\text{group}} = \sigma\!\left(W_c\, \hat{X}^{(3)}\right)
\end{equation}
where $\hat{X}^{(3)}$ is the resulting group-level embedding, and $p_{\text{group}}$ is the final illicit probability prediction obtained by performing a classification step on these embeddings. Sharing weights enforces consistency between the node and group levels while keeping the parameter count low.

\subsection{Multi-Task Loss}
\label{sec:loss}
Unlike standard GNNs that optimize a single objective, GAGNN relies on three supervised signals. The total loss $\mathcal{L}$ is a weighted sum of the node-level, transaction-level, and group-level losses:
\begin{equation}
  \mathcal{L} = c_1\,\mathcal{L}_{\text{group}} + c_2\,\mathcal{L}_{\text{node}} + c_3\,\mathcal{L}_{\text{trans}}
\end{equation}
where \(c_1,c_2,c_3 \in \mathbb{R}^+\) are hyperparameters and \(\mathcal{L}_{\text{group}}\), \(\mathcal{L}_{\text{node}}\) and \(\mathcal{L}_{\text{trans}}\) are the group-level, node-level, and transaction-level losses, respectively. Since nodes and groups are strictly classified as illicit or legitimate, their losses are always weighted Binary Cross-Entropy (BCE) functions:
\begin{align}
  \mathcal{L}_{\text{node}} &= \operatorname{BCE}_w\!\left(p_{\text{node}},\; y_{\text{node}}\right) \\
  \mathcal{L}_{\text{group}} &= \operatorname{BCE}_w\!\left(p_{\text{group}},\; y_{\text{group}}\right)
\end{align}
For the transaction classification, $\mathcal{L}_{\text{trans}}$ is a BCE loss for binary tasks, and a Cross-Entropy (CE) loss for multiclass classification.
\begin{equation}
  \mathcal{L}_{\text{trans}} = \begin{cases}
    \operatorname{BCE}_w\!\left(p_{\text{trans}},\; y_{\text{trans}}\right) & \text{if binary task} \\
    \operatorname{CE}_w\!\left(p_{\text{trans}},\; y_{\text{trans}}\right) & \text{if multiclass task}
  \end{cases}
\end{equation}
The positive-class weight $w$ is tuned to penalize false negatives, in the finance sector detecting most of the frauds is more important than maximizing the accuracy. By optimizing this joint loss, the model learns to identify money laundering at the individual, transaction, and community levels simultaneously.

\subsection{Building the Financial Graph}
Since the IBM AMLSim Dataset account (Node) features are very limited, we will leverage the transaction (Edge) features to derive the Node's ones.

Let \(\mathcal{N}(i)\) be the set of neighbors of account \(i\), \(e_{ij}\) the features vector of a transaction from account \(i\) to account \(j\), \(y_{ij}\) the label of that transaction. The feature vector \(x_i\) for the account \(i\) and his ground truth label \(\widehat{y_i}\) are defined as follows.
\begin{equation}
    x_i = \frac{1}{|\mathcal{N}(i)|} \sum_{j \in \mathcal{N}(i)} e_{ij}
\end{equation}
\begin{equation}
  \widehat{y_i} = \frac{1}{|\mathcal{N}(i)|} \sum_{j \in \mathcal{N}(i)} y_{ij}
\end{equation}
It's important to mention that in case of qualitative edge features or multiclass edge labels, the mean will be computed on the one-hot encoded vectors.

\section{Experimental Settings}

\subsection{Data Preparation}\label{dataprep}
In regard to enhance the performance of the models we perform some preprocessing steps on the dataset.
First of all, categorical features need to be converted in a numerical format; we opted for One-Hot Encoding, which works particulary well for our architecture since, when we average the features to create the nodes and groups representations, the one-hot vectors translate into proportions of the different categories providing like that meaningfull information. 

Secondly, we elaborated the timestamp by extrapolating from it the hour of the day, using cyclic encoding, and the day of the week, using a one-hot encoder. The cyclic representation is fundamental to preserve the daily periodicity of transactions.

We then normalized the financial amounts. Since money laundering datasets present a high number of outliers standard normalization techniques often tend to move the value of the legitimate transactions close to zero. For this reason a Robust Scaler was prefered to the standard one. It normalizes features using the median and the interquartile range (IQR), according to the following formula:
\begin{equation}
    x_{\text{scaled}} = \frac{x - Q_2(x)}{Q_3(x) - Q_1(x)}
\end{equation}
where $Q_2(x)$ is the median, and $Q_1(x)$ and $Q_3(x)$ are the 25th and 75th percentiles of the feature values. This prevents extreme values from distorting the distribution of the data.

Finally, we extrapolated the multiclass labels from \texttt{HI-Small\_Patterns.txt} obtaining the categorical feature. As before, we then apply one-hot encoding to allow the model to understand it.

\subsection{Train, Patience, Validation and Test Split}
Anti Money Laundering algorithms are usually performed on the new incoming transactions to detect fraudulent activity. This means that the models must learn from the past to predict the future. For this reason, splitting the dataset randomly would inevitably cause future information to leak into the past. To avoid that we decided to split our dataset by using 3 temporal thresholds \(t_1, t_2, t_3\) that define the training, patience, validation and test sets as follows.
\begin{align}
    \mathcal{D}_\text{train} &= \{d \in \mathcal{D} \vert t(d) \le t_1 \} \\
    \mathcal{D}_\text{patience} &= \{d \in \mathcal{D} \vert t_1 < t(d) \le t_2 \} \\
    \mathcal{D}_\text{val}   &= \{d \in \mathcal{D} \vert t_2 < t(d) \le t_3 \} \\
    \mathcal{D}_\text{test}  &= \{d \in \mathcal{D} \vert t(d) > t_3 \}
\end{align}
where \(t(d)\) is the timestamp of the transaction $d$, and \(t_1, t_2\) and \(t_3\) are specially picked so that \(|\mathcal{D}_\text{train}| \approx 0.7 |\mathcal{D}|\), \(|\mathcal{D}_\text{patience}| \approx 0.075 |\mathcal{D}|\), \(|\mathcal{D}_\text{val}| \approx 0.075 |\mathcal{D}|\) and \(|\mathcal{D}_\text{test}| \approx 0.15 |\mathcal{D}|\). 
The patience set is exclusively used to trigger early stopping during both model selection and training. The validation set is instead kept strictly for evaluating and comparing models during the selection phase, preventing the evaluation metric from being biased by the early stopping mechanism.

During the training phase, since we no longer need 4 different subsets, the train set becomes \(\mathcal{D}_\text{train} \gets \mathcal{D}_\text{train} \cup \mathcal{D}_\text{patience}\), the validation will be used for the early stopping \(\mathcal{D}_\text{patience} \gets \mathcal{D_\text{val}}\) and the test set remains untouched to provide an unbiased evaluation of the model performance.
This ensures that the model always trains on a contiguous block of time and prevents data from the future to leak into the past.

It's important to mention that, in order to prevent data leakage, the Robust Scaler was fitted exclusively on the transactions belonging to the training split, and the resulting parameters ($Q_1, Q_2, Q_3$) were then used to independently transform the patience, validation and test sets.

Finally, in order to address the class imbalance, we decided to apply downsampling on the training set.
For the binary task, the majority class (legitimate accounts) is downsampled to match the number of illicit accounts, achieving a 1:1 ratio. 
For the multiclass task, the legitimate class is downsampled to match the total sum of all illicit instances across the different illicit patterns. This achieves a 1:1 ratio between legitimate and overall illicit samples, while preserving the natural distribution and relative frequencies among the specific illicit classes. 
The validations and test sets remain untouched.

\section{Model Selection and Training settings}
In this section we describe and explain our choices for the training settings and the modles' hyperparameters. We first discuss the general settings shared amongst all the experiments, then we deep dive into the architectural choices and hyperparameter tuning for each class of models we evaluated. 

\subsection{Optimizer}
As suggested by Cheng et al. \cite{mainpaper}, we decided to adopt the Adam optimizer \cite{adam} as the optimization algorithm for all our models. The original implementation suggested a learning rate of \(0.001\) and a batch size of \(128\). 
With our dataset these settings led to a very unstable convergence, therefore we decided to lower the learning rate to \(\eta = 0.0001\) which, together with gradient clipping at a maximum norm of \(5.0\), ensured smoother and more reliable training dynamics. Furthermore we also changed the batch size to \(256\) to better exploit the GPU usage.

\subsection{Subgraph Sampling}
Due to the prohibitive dimension of the financial graph, fitting the models directly to the entirety of it is not a feasible option in both terms of memory and tim.

To address this, we employed a mini-batch subgraph sampling strategy using \texttt{NeighborLoader} from PyTorch Geometric~\cite{pyg}.
The loader operates by sampling a fixed number of neighbors per hop. This is governed by the \texttt{num\_neighbors} \(=[a,b,c,\dots]\) parameter. Meaning that for each target node in the batch, the loader samples $a$ of its immediate neighbors; for each of those \(a\) sampled neighbors, it further samples $b$ of their neighbors and so on. 
In our experiments, we set \texttt{num\_neighbors = [15, 10, 10]} across $L = 2$ or \(L=3\) hops depending on the model architecture. This preserves the local graph topology while keeping the computational cost manageable.

This sampling strategy is only used during {training}. For validation and {testing}, we set \texttt{num\_neighbors = [-1, -1, -1]}, meaning that all neighbors are included. This guarantees an unbiased evaluation of the model's performance on the realistic, imbalanced data.

\subsection{Early Stopping}
To prevent overfitting we employed an early stopping mechanism that monitors the loss on the patience set \(\mathcal{D}_\text{patience}\). Training is stopped when no improvement is observed for a specified number of consecutive epochs (the \emph{patience}). During the model selection phases, we set a maximum of $3000$ epochs with a patience value of $p_{\text{selection}}=100$; during the final training phase, we set a maximum of $6000$ epochs with a patience value of $p_{\text{training}}=150 $, to allow the model to fully converge on the selected hyperparameters. These settings are shared across all the experiments.

\subsection{Hyperparameters}
We begin by listing the hyperparameters that will need to be tuned across all the different models.
\paragraph{Loss function hyperparameters} 
\begin{itemize}
  \item \(c_1\): Weight for the group-level loss \(\mathcal{L}_{\text{group}}\).
  \item \(c_2\): Weight for the node-level loss \(\mathcal{L}_{\text{node}}\).
  \item \(c_3\): Weight for the transaction-level loss \(\mathcal{L}_{\text{trans}}\).
  \item \(w\) (\texttt{laundry\_weight}): Positive-class weight used in the BCE loss.
\end{itemize}
\paragraph{GAGNN hyperparameters}
\begin{itemize}
  \item \(\beta\): Trade-off parameter in the Extended Markov Random Field (eMRF) layer that balances the influence of topological similarity \(\varepsilon\) and attribute similarity \(R_\zeta\) (Section~\ref{sec:emrf}).
  \item \texttt{mlp\_hidden\_dim}: Dimension of the hidden layers in the \(\operatorname{MLP}_{\text{node}}\), used to map the refined embeddings \(X^{(3)}\) to node-level classification logits (Section~\ref{sec:node_clf}).
  \item \texttt{nn\_t\_hidden\_dim}: Dimension of the hidden layers in the \(\operatorname{MLP}_{\text{edge}}\), used to compute the transaction probability \(p_{\text{trans}}\) (Section~\ref{sec:group_layer}).
  \item \texttt{out\_dim}: Dimension \(d_{\text{out}}\) of the enriched embeddings \(X^{(2)}\) (Section~\ref{sec:encoder}).
\end{itemize}
\paragraph{GAT hyperparameters}
\begin{itemize}
  \item \texttt{hidden\_dim}: Dimension of the hidden layers in the message passing steps.
  \item \(L\) (\texttt{num\_layers}): Number of message passing layers, determining the multi-hop receptive field of the GNN.
  \item \(H\) (\texttt{heads}): Number of attention heads.
\end{itemize}
\paragraph{GIN hyperparameters}
\begin{itemize}
  \item \texttt{hidden\_dim}: Dimension of the hidden layers in the message passing steps.
  \item \(L\) (\texttt{num\_layers}): Number of message passing layers, determining the multi-hop receptive field of the GNN.
  \item \texttt{gin\_mlp\_hidden}: Dimension of the hidden layers of the \(\operatorname{MLP}\) used inside the GIN UPDATE function (Section~\ref{sec:gin}).
\end{itemize}
Due to the very high number of hyperparameters that need to be tuned, we decided to split the model selection process into two distinct phases. The first one concetrates on finding the best values for the parameters involved in the loss function by keeping the architectural hyperparameters fixed to reference values suggested by Cheng et al. \cite{mainpaper}. 
The second phase instead focuses on tuning the architectural hyperparameters (hidden dimension, number of layers, number of attention heads, etc.) keeping the loss function weights fixed to the values found in the first one.

\subsubsection{Loss Function Hyperparameters}
\label{sec:loss_hp}

\subsubsection{Architecture Hyperparameters}
\label{sec:gagnn_hp}
The second phase consists in finding the optimal values for the architectural hyperparameters, keeping the loss function weights fixed to the values found in the first phase. This allows to use the \textit{validation loss} \(\mathcal{L}_{\text{val}}\) instead of the validation F1-score as selection criterion; this is a better choice in this case since the F1-score metric is defined by strict decisions boundaries and therefore is not continuous and more sensitive to small fluctuations.

We will perform four different model selections, one for each experiment: GAGNN with GAT backbone for the binary task, GAGNN with GIN backbone for the binary task, GAGNN with GAT backbone for the multiclass task and GAGNN with GIN backbone for the multiclass task. Two hyperparameters grid are used, since they are shared between binary and multiclass tasks with the same backbone GNN. As possible values we chose options around those of the reference paper; the hyperparameters grids for GAT and GIN backbones are reported in Table \ref{tab:phase2_gat} and Table \ref{tab:phase2_gin} respectively.

\subsubsection{Baseline Models Hyperparameters}
\label{sec:baseline_hp}

For the baseline models (GIN and GAT) we used as hyperparameters the same values obtained for the internal GNN encoder of their respective GAGNN counterpart. 
This choice stems from the need to understand how much the GAGNN architecture enhances the GNNs capacity of detecting fraudulent transactions, without the confounding factor of different hyperparameter settings.
